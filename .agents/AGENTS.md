# 项目专属开发规范 (Island Diary)
- **技术栈**: 使用 Flutter + Dart
- **平台优先**: 页面优先移动端体验
- **优先使用成熟开源方案**: 面对复杂需求（如物理引擎、复杂算法、图形渲染、特定功能模块等），严禁盲目手写或重复造轮子。必须优先调研并推荐引入市面上工业级、成熟稳定的开源第三方库/方案（如 `forge2d`、`flutter_animate` 等）进行实现，避免引入不必要的维护成本与边界 Bug。
- **UI 元素**: 少用复杂图表，多用卡片、胶囊、日历、情绪天气
- **组件化**: 组件必须可复用
- **屏幕适配**: 代码要适配不同屏幕
- **动画策略**: 动画优先考虑 Flutter 原生动画、Lottie、Rive、帧序列的取舍；复杂物理场景优先使用成熟物理引擎
- **API 使用规范**: 始终推荐使用官方最新推荐的新属性，坚决避免使用被废弃 (deprecated) 的属性或方法
- **代码结构**: 保持文件精简，避免文件过于臃肿，必要时进行合理的模块和组件拆分
- **语言要求**: 必须用中文回答，包括思考过程
- **异常与日志**: 避免直接使用 print，统一使用项目封装的 logger；在涉及到文件读写、权限请求等容易失败的操作时，必须有完整的 try-catch 结构和对用户的错误提示 UI
- **消息弹窗**: 
  - 顶部通知必须使用项目封装的 `showTopToast(context, 'msg')`。
  - 交互式弹窗（带确认/取消按钮）必须使用 `IslandDialog.show(...)`。
  - 避免直接使用原生 `SnackBar` 或 `AlertDialog`。
- **注释规范**: 代码中的所有注释必须使用中文。对于所有全局状态、复杂的算法逻辑、关键的生命周期重写，必须加上清晰的中文文档注释（///）
- **UI 设计系统 (Design Tokens)**: 新建页面或组件时，禁止硬编码颜色（如 Hex）和固定边距，必须统一使用 `AppColors`（支持暗黑模式自动切换）和 `AppSpacings`，确保风格一致。
- **文本常量提取 (i18n)**: 避免在 UI 代码中直接写死中文文本（特别是通用词汇如“确定”、“取消”），必须统一使用或添加到 `lib/core/constants/app_strings.dart` 中的 `AppStrings`。
- **UI 动效与交互系统 (Animations)**: 开发新页面、新组件、或者重构已有 UI 时，必须自动参考并遵循 `island-diary-animations` 规范，实现高质量的微交互和页面转场。
- **Dart 语法规范**: 全面拥抱 Dart 2.17+ 的现代语法糖，例如在构造函数中必须使用 `super.key` 替代传统的 `Key? key ... : super(key: key)`，保持代码极致简练。
- **交互式引导与追问**: 在开始回答复杂问题、制定方案或执行任务之前，必须先向用户提问以收集必要信息或确认意图。一次只能向用户提出 **一个** 最重要的问题。必须根据用户的回答进行下一步追问，直到所有疑点澄清后再开始实际工作。对于明显非常简单、明确的任务（如简单的代码格式化、修复拼写错误、运行固定命令等），可以直接理解并执行，无需提问。
</RULE>
